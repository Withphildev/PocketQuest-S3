# Blue slime sprite candidate — first enemy artwork review

2026-10-12. Blue slime only, establishing the template before slime recolors, dire wolves and goblins. These later enemies are not created/implemented in this milestone. Firmware, combat balance, saves, Wi-Fi/screens and production scenery unchanged. No new firmware BIN, device access, automatic flashing, or GitHub push performed.

Imagegen skill used the built-in image generation tool with the owner's blue slime reference, followed by one transparency-cleanup edit. Source images and exact prompts recorded in web/artwork-sources/slime-blue. Final source source-clean.png is actual 1672×941 RGBA, not an exact native atlas. No color-key background removal or manual repainting used. Deterministic preparation infers two rows and four columns from transparent gutters, uniformly nearest-neighbor samples every pose using the same inverse scale 11.25, and pads frames transparently. Full alpha is preserved; faint soft contour pixels can extend below the significant-alpha ground baseline but no painted pixels reach the canvas border. This differs from intentionally discarded inter-frame ghost pixels in the original attempt; clean source generated by imagegen is retained.

## Contract and states

Eight separate 48×48 RGBA PNG frames; atlas 192×96; fixed ground pivot (24,42), facing west/left in three-quarter presentation. Visible idle body approximately 30px tall, smaller than Nova. Foot/base X derives from inferred cell center and Y from significant paint base (alpha >=128). Pose/body displacement and alignment are provisional until owner animation review; no per-frame stretching. An attack lunge is a cosmetic pose, not movement or a hitbox.

Frame order: idle-0, idle-1, block-0, attack-0 (wind-up), attack-1 (lunge), attack-2 (recovery), hurt-0, defeated-0. State manifest slime.json includes no hitboxes, damage stats or implemented blocking mechanic. Preview durations: idle 300ms each, block 500ms, attack 100/120/200ms, hurt 500ms, defeated 1000ms. Those are review timings, not finalized gameplay timing. Defeated pose is a harmless flattened puddle with closed eyes.

Preview GIF cycles the poses beside Nova on a 240×135 composition enlarged 3× with nearest-neighbor scaling. It is an artwork demonstration, not a new browser mini-game or actual StickS3 display capture. GIF palette can quantize colors and is not a gameplay asset. Full-alpha PNGs remain authoritative.

## Browser and StickS3 reuse

Web: use transparent PNGs with nearest-neighbor rendering and fixed ground pivot. The new slime state manifest is not yet wired into the existing world renderer or local device landing page. No browser RPG functionality added.

StickS3: Slime-Blue.rgb565 contains little-endian uint16 row-major pixels, frames in the manifest order; Slime-Blue.mask1 has MSB-first visibility bits (alpha >=128). SlimeBlueSprites.h is the equivalent PROGMEM-ready C++ export with pq_slime::drawFrame(display,frameIndex,groundX,groundY), masked same-color horizontal runs, and invalid frame guards. At enemy anchor (186,82) the 48×48 canvas begins at (162,40). Repaint the background between animation frames. RGB565 quantization/binary alpha are expected format conversion, not lossless image optimization. The host draw test passes; actual Arduino/ESP branch compilation and hardware timing still need a future authorized firmware integration.

Future recolors should share these pose shapes/timings and preserve eyes, highlights, alpha and anchors. Exact palette rules and variant colors still need approval. Planned relative difficulty remains slimes < dire wolves < goblins; no stats assigned here.

## Reproduce

Python/Pillow 12.3.0 and C++ compiler; run from repository root after preparing existing female Nova v2 idle assets as documented in CHECKPOINT_V0_1_5.md:

```sh
python3 web/tools/prepare-slime.py web/artwork-sources/slime-blue/source-clean.png web/build/slime-blue
python3 web/tools/test-slime.py web/build/slime-blue
c++ -std=c++17 web/tools/test-slime.cpp -o /tmp/pocketquest-test-slime
/tmp/pocketquest-test-slime
python3 web/tools/asset-storage-budget.py /tmp/pocketquest-slime-budget.json --female-v2 --sword --slime
```

Storage script requires littlefs-python 0.19.0. It reports the existing forest standalone preview, not this GIF. Preparation requires the existing Nova idle PNG only for the review GIF, not for slime extraction. Package includes that dependency.
